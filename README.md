# 抽選・予約ウォッチャー(deal-watcher)

トレーディングカード(ポケカ・ワンピース・遊戯王・ドラゴンボール・MTG)、限定スニーカー(Nike SNKRSなど)、
お酒(ウイスキー・日本酒)、限定モデルの時計、限定車の
**抽選・予約・発売情報**を定期的に見回り、**新しい情報だけ**を Discord に通知するツールです。
GitHub Actions で自動実行するので、パソコンを付けっぱなしにする必要はありません。

- 言語: Python 3.11 以上(動作確認は 3.13)
- 使うライブラリ: `requests` / `beautifulsoup4` / `feedparser`
- 通知: Discord の Webhook(Embed形式。タイトル・カテゴリ・URL・取得日時つき)

## ファイル構成

| ファイル | 役割 |
| --- | --- |
| `main.py` | 本体。情報源の取得、重複チェック、Discord通知をすべて行う |
| `requirements.txt` | 必要なライブラリ一覧 |
| `.github/workflows/checker.yml` | GitHub Actions の設定(30分おきに実行) |
| `notified_history.json` | 通知済みの記録。**初回実行後に自動で作られる**(手で作らなくてよい) |
| `test_main.py` | ネットにつながずに動くテスト(45件) |

### 正直に書いておく制限

- **ポケモンセンターオンラインは、トップページの「お知らせ」欄を直接読んでいます。**
  お知らせ専用の一覧ページは無く、`robots.txt` でも全ページ許可されていることを確認しました。
  ただし「お知らせ」欄に載るのは直近の十数件だけなので、Googleニュース経由の検索も併用しています。
- **ワンピース・ドラゴンボール・MTGのメーカー公式ページは直接見ていません。**
  ワンピースカード公式のニュース一覧はJavaScriptで後から読み込まれる作りで、
  ドラゴンボール・MTGの公式ページも一覧をそのまま読み取れる作りではなかったため、
  ゲオの一覧と Googleニュース経由で拾っています(公式より数時間〜1日遅れることがあります)。
- **プレミアムバンダイの一覧と atmos の抽選一覧は、GitHub Actions(海外のサーバー)からは読めませんでした。**
  日本からは読めますが、Actions からはプレミアムバンダイは記事が返らず、atmos は 403 で拒否されます。
  そのためプレミアムバンダイは Googleニュース経由にし、atmos は情報源に入れていません(Nike SNKRS は直接読めます)。
- **時計・車はGoogleニュースだけが情報源です。** メーカーやブランドの公式ページはそれぞれ作りが違い、
  一括で読み取る方法がないためです。コンビニの腕時計や、車以外の「限定」記事が混ざることがあります。
- **日本酒はほとんど拾えません。** 動作確認時点では、直近7日のGoogleニュースに本物の日本酒の抽選記事が
  ほぼ出てきませんでした(ウイスキーの記事が混ざる程度)。特定の銘柄や酒販店の公式ページを見たい場合は、
  下の「情報源を追加する」で足してください。
- **Googleニュースには関係の薄い記事も混ざります。** キーワードで絞っていますが、ゼロにはできません。
- **個別カードショップは、1軒ずつは監視していません。** 各店は自店のブログやSNSで告知するだけの
  ところが多く、店ごとに監視する仕組みを作るのは現実的ではないためです。代わりに、店舗横断で抽選情報をまとめている
  「トレカ抽選ナビ」の地域別ページ(福島県・栃木県・埼玉県・東京都)を情報源にしています。ただし、このページには応募が締切済みで
  購入期間だけ残っている商品が混ざることがあるので、応募期限は必ずリンク先の店舗ページで確認してください。
- 情報源のサイト構成が変わると、HTML読み取り(ポケカ公式・ポケモンセンターオンライン・遊戯王公式)とNikeの部分は
  動かなくなることがあります。
  同じ情報源が **6回連続で失敗** すると、Discord に警告が届きます。

## 仕組み(初心者向け)

1. GitHub Actions が30分おきに `main.py` を動かします。
2. 各情報源を **3秒以上あけて1つずつ** 見に行きます(相手のサーバーに負担をかけないため)。
3. `notified_history.json` にない情報だけを「新着」として Discord に送ります。
4. 通知した分を `notified_history.json` に記録し、GitHub に自動コミットします。次回は同じ情報を送りません。

安全のための工夫:

- 自分のことを名乗る User-Agent を付け、ボット向けの決まり(robots.txt)に従います(HTML情報源のみ確認)。
- **初回実行は「既読登録だけ」** です。今掲載されている情報を全部通知するとDiscordが埋まってしまうため、
  最初の1回は「監視を開始しました」と送るだけで、以後の新着から通知します。
- **後から情報源を追加したときも、その情報源の初回は「既読登録だけ」** です(「情報源を○件追加しました」とだけ届きます)。
- 1回の通知は最大20件。超えた分は次回以降に回します。
- 記録ファイルが壊れていたら、勝手にリセットせず止まります(全件再通知の事故を防ぐため)。
- 記事タイトルに含まれる `@everyone` などが Discord で効かないようにしてあります。
- Webhook URL はログに出ません(出るときは伏せ字になります)。

## 1. Discord の Webhook URL を取得する

Webhook URL は「このチャンネルに投稿してよい」という**合鍵**です。
他人に知られると、誰でもそのチャンネルへ投稿できてしまうので、**絶対に公開しないでください**。

1. Discord で通知を受け取りたいサーバーを開きます(なければ「サーバーを追加」で自分専用のサーバーを作ると安全です)。
2. 通知用のテキストチャンネル(例: `#抽選情報`)の横にある **⚙(チャンネルの編集)** を押します。
3. 左メニューの **「連携サービス」→「ウェブフック」→「新しいウェブフック」** を選びます。
4. 名前(例: `抽選ウォッチャー`)を付けます。
5. **「ウェブフックURLをコピー」** を押します。`https://discord.com/api/webhooks/数字/英数字...` の形です。

※ 画面の名前は Discord のアップデートで少し変わることがあります。見つからないときは、
Discord公式ヘルプの「Intro to Webhooks」を検索して参照してください。

もしURLを誰かに見せてしまったら、同じ画面でそのウェブフックを**削除して作り直す**と、古いURLは使えなくなります。

## 2. GitHub にアップロードして Secret を登録する

### 2-1. リポジトリを作る

このフォルダ(`deal-watcher`)を、**単独のGitリポジトリ**としてアップロードします。
このフォルダの外側(親フォルダ)には別のファイルが入っていることがあるので、親ごとではなく、このフォルダだけをアップロードしてください。

1. GitHub で **New repository** を作ります。
   - 名前は自由(例: `deal-watcher`)。
   - Public(公開)かPrivate(非公開)かは、後述の「無料枠の分数」を読んで決めてください。
     Publicだとコードや通知履歴(記事のURL)が誰にでも見えますが、Webhook URLはSecretなので見えません。
   - 「Add a README」などのチェックは**入れない**でください(空のままにします)。
2. ターミナルで、このフォルダに移動して次を実行します(`あなたのユーザー名` は書き換えてください)。

```bash
cd deal-watcher  # deal-watcher フォルダの中へ移動する
git init -b main
git add .
git status
```

`git status` で、`.env` のような秘密のファイルが含まれていないことを確認してから続けます。

```bash
git commit -m "初回コミット"
git remote add origin https://github.com/あなたのユーザー名/deal-watcher.git
git push -u origin main
```

### 2-2. Webhook URL を Secret に登録する

Secret は、GitHub が暗号化して保管する秘密の入れ物です。Webhook URL はコードに書かず、ここに入れます。

1. GitHub のリポジトリページを開きます。
2. **Settings → Secrets and variables → Actions** を開きます。
3. **New repository secret** を押します。
4. 次のように入力して **Add secret** を押します。
   - **Name**: `DISCORD_WEBHOOK_URL`(この名前のとおりに入力)
   - **Secret**: 手順1でコピーしたWebhook URL

### 2-3. 動かしてみる

1. リポジトリの **Actions** タブを開きます。
   (初めてのときは「ワークフローを有効にする」ボタンが出ることがあります)
2. 左の **Deal Checker** を選び、**Run workflow** を押すと、すぐに手動で実行できます。
3. 成功すると Discord に「監視を開始しました」と届きます(初回は既読登録のみ)。
4. その後は30分おきに自動で動き、新着があれば通知されます。

## 3. ローカル(自分のパソコン)でテストする

Python 3.11 以上が必要です。Mac 標準の `python3` は古いことがあるので、`python3 --version` で確認してください。

```bash
cd deal-watcher  # deal-watcher フォルダの中へ移動する
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 3-1. ネットにつながずにテスト(45件)

```bash
python -m unittest -v
```

最後に `OK` と出れば成功です。

### 3-2. ドライラン(実際には送らない予行演習)

`--dry-run` は、**情報源には実際にアクセスしますが、Discordへは送信せず、記録ファイルも書き換えません。**
送る予定の内容だけを画面に表示します。Webhook URL は形さえ合っていれば動くので、仮のものでかまいません。

```bash
export DISCORD_WEBHOOK_URL="https://discord.com/api/webhooks/000000000000000000/DUMMY_TOKEN"
python main.py --dry-run
```

- 初回相当の動きが表示されます(「既読登録する動きになります」)。
- 通知内容(Embed)を確認したいときは、既読登録を飛ばす `--no-baseline` を付けます。

```bash
python main.py --dry-run --no-baseline
```

- 情報源を1つだけ試したいときは `--only` を使います(名前の一部でOK)。

```bash
python main.py --dry-run --no-baseline --only Nike
```

### 3-3. 本物のWebhookで1回だけ送ってみる(任意)

```bash
export DISCORD_WEBHOOK_URL="コピーしたWebhook URL"
python main.py
```

- **このコマンドは実際にDiscordへ送信し、`notified_history.json` も作成します。**
- Webhook URL を `.env` などのファイルに書く場合は、`.gitignore` で除外済みですが、
  コミットしていないか必ず `git status` で確認してください。
- ローカルで本番実行したあとに作られた `notified_history.json` は、GitHub側の記録と食い違います。
  GitHub Actions で運用するなら、ローカルの `notified_history.json` はコミットせず削除しておくのが無難です。

### オプション一覧

| オプション | 意味 |
| --- | --- |
| `--dry-run` | 送信も記録の書き換えもしない予行演習 |
| `--no-baseline` | 初回でも既存分を通知する(既読登録を飛ばす) |
| `--only 名前` | 名前にその文字を含む情報源だけ実行 |
| `--history パス` | 履歴ファイルの場所を変える |
| `--interval 秒` | リクエスト間隔(標準は3秒) |
| `-v` | 詳しいログを表示 |

終了コード: `0`=正常、`1`=取得または送信に失敗があった、`2`=設定ミス(Webhook URLが未設定など)。

## 情報源を追加する

`main.py` の `SOURCES` というリストに1つ足すだけです。

### RSS(ニュースサイト・ブログなど)

```python
RssSource(
    name="○○酒店の新着",          # 通知に表示される名前
    category=CATEGORY_LIQUOR,     # CATEGORY_CARD / CATEGORY_SNEAKER / CATEGORY_LIQUOR / CATEGORY_WATCH / CATEGORY_CAR
    url="https://example.com/feed.xml",
    include=LOTTERY_KEYWORDS,     # このどれかの言葉をタイトルに含むものだけ通す
    exclude=PRIZE_KEYWORDS,       # (任意)このどれかを含むものは外す。懸賞記事よけに使う
),
```

Googleニュースの検索を足したいときは、もっと短く `news_source("検索したい言葉", CATEGORY_LIQUOR)` と書けます。
検索語は `"ロレックス OR オメガ 抽選"` のように `OR` でつなげられます。

### HTMLの一覧ページ

```python
HtmlListSource(
    name="○○公式 お知らせ",
    category=CATEGORY_CARD,
    url="https://example.com/news/",
    item_selector="a.news-item",   # 1件ぶんのリンクを指すCSSセレクタ
    title_selector=".title",       # タイトル部分(省略するとリンク内の文字全体)
    include=RELEASE_KEYWORDS,
),
```

新しい形式(APIなど)に対応したいときは、`Source` を継承して `fetch(self, http)` を作れば追加できます。
追加する前に、そのサイトの利用規約と `robots.txt` を確認してください。ログインが必要なページや、
ボット対策で拒否されるサイトは対象にしないでください。

## 注意点

- **実行時刻は目安です。** GitHub Actions の定期実行は混雑すると数分〜数十分遅れることがあります。
  このツールは毎時0分を避けて `7分・37分` に設定しています。
- **無料枠の分数に注意。** 公式ドキュメント上、Freeプランのプライベートリポジトリは月2,000分が上限で、
  公開リポジトリの標準ランナーは無料です。30分おきだと月およそ1,440回の実行になります。
  予行演習では全情報源の取得に約1分かかったので、1回あたり1〜2分かかると考えると、
  **非公開リポジトリでは無料枠を超える可能性があります**(1回あたりの課金の切り上げ単位は確認できていません)。
  15分おきならさらに倍です。非公開で使うなら、次の「実行間隔の変更」で1時間おきにするのが無難です。
  料金や無料枠は変わることがあるので、GitHub公式ドキュメントの「GitHub Actions の課金について」で最新を確認してください。
- **60日間なにも更新がないと、定期実行が自動停止することがあります**(公開リポジトリの場合)。
  止まったら Actions タブから再開できます。このツールは履歴を自動コミットしますが、それが「更新」として数えられるかは確認できていません(未確認)。
  Discordに通知が来なくなったら、Actionsタブで止まっていないか確認してください。
- 履歴の書き戻しに `contents: write` の権限を使っています。**mainブランチに保護設定(直接pushを禁止する設定)を入れていると、書き戻しが失敗**します。
- **実行間隔の変更:** `.github/workflows/checker.yml` の `cron: "7,37 * * * *"` を書き換えます。
  15分おきなら `"7,22,37,52 * * * *"`、1時間おきなら `"7 * * * *"` です(無料枠の注意を確認してから)。
- Python 3.11以上を前提に書いていますが、実際にテストしたのは 3.13(ローカル)です。
  GitHub Actions は 3.12 を指定しています。
- HTMLの読み取りは、robots.txt の判定に標準ライブラリを使っているため、ワイルドカード(`*`)を使った細かい指定は
  正確に解釈できない場合があります。
- **Webhook URL を絶対にコミットしない**でください。もし公開してしまったら、Discordでそのウェブフックを削除して作り直し、
  Secret も新しいURLに更新してください。
- このツールは個人の趣味用です。抽選への応募や購入は自動化していません。各社の規約を守って、ご自身で応募してください。

## うまく動かないとき

| 症状 | 対処 |
| --- | --- |
| `環境変数 DISCORD_WEBHOOK_URL が未設定、または Discord Webhook の形式ではありません` | 環境変数(ローカル)またはSecret(GitHub)の設定を確認。名前は完全一致で `DISCORD_WEBHOOK_URL`。値は `https://discord.com/api/webhooks/数字/英数字` の形で、前後の空白や引用符が入っていないか |
| Actionsが動かない | Actionsタブで有効化されているか、Secretが登録されているか確認 |
| 履歴のpushで失敗する | ブランチ保護の設定と、`Settings → Actions → General → Workflow permissions` が読み書き可か確認 |
| 通知が来ない | 新着がないだけの可能性があります。`Run workflow` の実行ログで「新着: 0件」などを確認 |
| `notified_history.json を読み込めません` で止まる | ファイルの中身を確認し、直せなければ削除(削除後の初回は既読登録のみ行われます) |
